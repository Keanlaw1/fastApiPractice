# 2-й семестр FastApi

## Что сделано по заданиям

- **Задание 1 — FastAPI** <br>
Модели из Блогикума переписаны на SQLAlchemy. База данных SQLite
Есть категории, места, посты, комментарии и упрощенный пользователь. Для постов сделаны GET, POST, PUT и DELETE

- **Задание 2 — PostgreSQL** <br>
Подключил PostgreSQL вместо SQLite. Вынес запросы к базе в repositories.py и добавил функции для всех пяти моделей

- **Задание 3 — Alembic** <br>
Сгенерировал первую миграцию и проверил, что она создаёт все таблицы в пустой базе PostgreSQL

- **Задание 4 — Обработка ошибок** <br>
Возвращается:<br>
`409` -- если имя пользователя занято<br>
`404` -- если пост или автор не найден<br>
`422` -- если данные запроса не прошли проверку

- **Задание 5 — Authentication** <br>
Добавил регистрацию с хешированием пароля, вход с выдачей JWT и проверку прав

- **Задание 6 — Docker**<br>
Приложение и PostgreSQL запускаются через Docker Compose. Настройки читаются через Pydantic Settings, миграции применяются автоматически. Действия пользователей записываются в журнал

Также были добавлены: пагинация постов и комментариев, получение поста по ID, категории, локации и отдельную таблицу изображений.
## Запуск

Нужен Docker Desktop<br>
Откройте терминал в папке с `compose.yaml`

```powershell
cp .env_example .env
```

Откройте `.env`. Задайте свой пароль в `POSTGRES_PASSWORD`
Для `JWT_SECRET_KEY` сгенерируйте ключ командой:

```powershell
docker run --rm python:3.13-slim python -c "import secrets; print(secrets.token_hex(32))"
```

Скопируйте полученную строку в `JWT_SECRET_KEY` и сохраните `.env`

Запустите проект:

```powershell
docker compose up --build -d
```

При первом запуске Docker скачает образы, установит зависимости и создаст таблицы через Alembic. Бд будет пустой

Откройте [Swagger](http://127.0.0.1:8001/docs).

Проверить состояние контейнеров:

```powershell
docker compose ps
```

Посмотреть журнал приложения:

```powershell
docker compose logs -f app
```

Остановить проект с сохранением базы и фотографий:

```powershell
docker compose down
```

Запустить снова:

```powershell
docker compose up -d
```

Данные хранятся в томах Docker. Команда `docker compose down -v` удаляет эти тома вместе с базой и фото


## Как проверить API

Все запросы выполняем в Swagger

### 1. Создать пользователя

Откройте **POST `/users/`** и отправьте:

```json
{
  "username": "Proverka",
  "password": "Proverka"
}
```
Ожидается `201` Если имя занято, сервер вернёт `409` В таком случае выберите другое имя<br>
Пароль должен содержать от 8 до 128 символов. В базе сохраняется его хеш

### 2. Авторизоваться

Войдите через Authorize внутри Swagger<br>
Swagger получит токен через **POST `/token/`** и будет передавать его в защищённых запросах<br>
Проверьте **GET `/users/me/`** В ответе должны быть ваши `id` и `username`<br>
По умолчанию токен действует 30 минут. После истечения срока нужно войти снова

### 3. Создать категорию и локацию

В **POST `/categories/`** отправьте:

```json
{
  "title": "Путешествия",
  "description": "Посты о поездках",
  "slug": "travel"
}
```

`slug` должен быть уникальным. Для него разрешены латинские буквы, цифры, дефис и подчёркивание

В **POST `/locations/`** отправьте:

```json
{
  "name": "Саратов"
}
```

Запомните ID категории и локации. Их также можно посмотреть через **GET `/categories/`** и **GET `/locations/`**<br>
Отдельную категорию или локацию можно получить через **GET `/categories/{category_id}/`** и **GET `/locations/{location_id}/`** соотвественно

### 4. Создать пост

Откройте **POST `/posts/`**<br>
Заполните `title` и `text`, категория, локация и фото необязательные поля<br>
В поле `image` можно выбрать JPEG или PNG до 5 МБ<br>
Автор определяется по токену. После создания запомните `id` поста<br>
Если добавили фото, в ответе будут `image_id` и `image_url`. По ссылке можно открыть файл. Его также возвращает **GET `/images/{image_id}/`**

### 5. Посмотреть посты

**GET `/posts/`** возвращает посты от новых к старым по убыванию ID<br>
`limit` задаёт количество постов на странице, `page` задает номер страницы (По умолчанию `limit=10` `page=1`)<br>
Через **GET `/posts/{post_id}/`** можно получить один пост. В ответе рядом с ID категории и локации выводятся их названия.

### 6. Изменить пост

В **PUT `/posts/{post_id}/`** укажите ID своего поста и отправьте:

```json
{
  "title": "Новый заголовок",
  "text": "Новый текст",
  "category_id": null,
  "location_id": null
}
```

Для выбора категории и локации замените `null` на существующие ID<br>
Если эти поля пропустить, связи очистятся<br>
Редактировать пост может только его автор

### 7. Добавить комментарий

В **POST `/posts/{post_id}/comments/`** укажите ID поста и отправьте:

```json
{
  "text": "Круто емае!"
}
```

Автор комментария определяется по токену<br>
Посмотреть комментарии можно через **GET `/posts/{post_id}/comments/`**<br>
Для них также работают `limit` и `page`. Комментарии идут от старых к новым.

### 8. Поставить и снять лайк

В **POST `/posts/{post_id}/likes/`** укажите ID поста и выполните запрос<br>
Первый лайк вернёт `201`, повторный лайк того же пользователя вернёт `409`<br>
Количество лайков показывает **GET `/posts/{post_id}/likes/`**<br>
Снять свой лайк можно через **DELETE `/posts/{post_id}/likes/`** Пользователь определяется по токену<br>

### 9. Удалить пост

В **DELETE `/posts/{post_id}/`** укажите ID своего поста<br>
После удаления проверьте список через **GET `/posts/`**<br>
Удалять пост может только его автор

## Доступ и ошибки

Просмотр постов, комментариев, лайков, категорий, локаций и изображений доступен без входа<br>
Для создания постов, комментариев, категорий, локаций и работы со своими лайками нужен токен

Основные коды ошибок:

- `401` — нужен действующий токен или неверно введён логин и пароль
- `403` — попытка изменить или удалить чужой пост
- `404` — запрошенная запись или файл не найдены
- `409` — имя пользователя, slug категории или лайк уже существуют
- `422` — данные запроса не прошли проверку
